EMEM: A Content-Addressed, Verifiable Earth-Memory Protocol for AI Agents over Foundation-Model Embeddings

Jaya Kumari · Avijeet Singh — Vortx AI  ·  doi:10.5281/zenodo.20706893  ·  claims as of emem 64cfae5

Hand over the address,
not the sentence.

emem names each physical observation by a hash of its own signed bytes. An agent passes the name. Any receiver fetches the bytes, re-hashes them, and verifies the signature offline — without trusting the sender, its model, or the server.

Same bytes → same name. Anyone re-derives it with a stock BLAKE3; no emem code, no registry.

Deterministic CBOR in struct-declaration order, NaN and −0 canonicalised (not RFC 8949 key-sorted). The fact carries its signer and signing time; the ed25519 signature covers a Merkle root of fact CIDs. A CID therefore names one signed attestation: two attesters of the same value mint different CIDs and meet at the key (cell, band, tslot).

2 · The receiver

Resolve. Don’t trust.

  1. Resolve the token → the exact bytes GET /v1/facts/<cid>
  2. Re-hash them yourself. Does the name match?
  3. Bind the place: the cell in the token must equal the cell inside the signed fact.
  4. Verify the receipt offline: ed25519 over a domain-separated, length-prefixed preimage. 0.13 ms p50.
  5. Check history: RFC 6962-style log with BLAKE3; 2.54 M entries (29 Sep), co-signed by an independent operator, geo.qa.

A proof-less receipt signs an explicit ABSENT marker, so stripping a proof is detectable. An independent audit rejected 5/5 tampers, incl. a version downgrade.

4 · The finding

A paraphrase made two models agree — and both chose wrong.

One real Lahaul NDVI fact, Gemma-4-12B and Qwen2.5-7B. The lossy memory raised cross-model agreement while carrying the wrong decision.

Pre-registered test — accuracy vs agreement after a shared summary
full context (control)72/72 correct · 36/36 agree
compaction, free reasoning20/72 · 15/36  p = 0.109
compaction under pressure0/72 · 3/36  p = 0.035

Agreement between agents is not evidence of correctness. It is what a shared lossy summary produces. Fisher one-sided; two open models on one host; six scorer bugs found and fixed before the verdict.

5 · Handoff between agents

What Agent B gets right, by what Agent A handed over.

Long run — 599 turns, n = 1,624 per armwithin 1% · citable
emem bundle100% · 100%
BM25 retrieval35% · 0%

BM25 ties on short handoffs — say it plainly. What it cannot give the next agent is a citation that re-checks. Over long runs it drifts; the addressed bundle stays exact and every answer stays citable.

6 · Over foundation-model embeddings and fields

From a point to a field, same rule.

factone signed observation
<cell64>:<fact_cid>byte-identical
rastera Sentinel-2 field over an AOI, f32 grid
<aoi>:<band>:<tslot>:<derivation>derivation-bound
cubethat field through time: signed manifest of rasters
<aoi>:<band>:<lo>..<hi>:<derivation>derivation-bound
rasterset2–64 fields bound as one model inputderivation-bound
bundle
entitya set of facts · a shared name for a thinganchor

A field token binds a signed derivation: AOI, source scene, recipe, time and the artifact’s hash. The model receives a field, not a sentence about a field; the pixels can be evicted and rebuilt from the recipe. Embeddings (live: TESSERA, 128-D; earlier Clay v1.5, Prithvi-EO-2.0, Galileo) are signed as ordinary fact values labelled model_output — a learned representation, not a measurement. The embedding is not the memory; the addressable observation around it is.

7 · Boundary of the claim

What holds. What doesn’t.

Checkable

  • byte integrity of a cited fact
  • where and when it claims to be
  • who signed it, and when
  • that history was not rewritten
  • “nothing here” — absence is a signed fact
  • disagreement: kept and scored, never averaged

Not proved

  • that the observation is true
  • sensor calibration or model accuracy
  • that two sensors saw the same thing
  • that a sentence cites the right band
  • anything in orbit — edge signing is simulated (0.17% of a 40 ms frame)

8 · Reproduce this — now, on your phone or laptop
# pip install blake3      — no emem code involved
import blake3, base64, urllib.request as u
cid = "yqbolgeoycqkvj3zkxukb4bjw4odhpwvfzqo3fbgwf4spk45zala"
r = u.Request(f"https://emem.dev/v1/facts/{cid}", headers={"accept": "application/cbor"})
body = u.urlopen(r).read()                        # 509 bytes → value 918.0 m
name = base64.b32encode(blake3.blake3(body).digest()).decode().lower().rstrip("=")
assert name == cid                                # the bytes are their own name

# give your agent the same memory:
claude mcp add --transport http emem https://emem.dev/mcp
