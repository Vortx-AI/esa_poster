EMEM: A Content-Addressed, Verifiable Earth-Memory Protocol for AI Agents over Foundation-Model Embeddings

Jaya Kumari · Avijeet Singh — Vortx AI · paper doi:10.5281/zenodo.20706893 (v0.1.0; current method: whitepaper v3; emem 2.4.2 at 213e273 and 18adb67) · measurements 29–30 Sep 2026 · scripts: github.com/Vortx-AI/esa_poster
Agent A cites a satellite observation. What can agent B check without trusting A, A’s model, or us?

emem makes raw satellite observations addressable by place, band and time, each a signed record named by the BLAKE3 hash of its bytes. The exact evidence A cites survives compaction, a change of model and a handoff; B re-hashes it, verifies the log entry and receipt offline, and traces it to the source pixel. Agents cannot write observations, and a changed, rounded or forged value no longer matches its name.

1 · From scene to token

1.17 MB read from a 2.02 GB scene; the agent receives 84 characters

pixel: col = ⌊i + (E − X)/sx⌋, row = ⌊j + (Y − N)/sy⌋ in UTM 43N · ρ = (DN + o)·10⁻⁴, o = −1000 if baseline ≥ 04.00 (PC) · NDVI = (ρ₈ − ρ₄)/(ρ₈ + ρ₄) · SCL ∈ {0,1,8,9,10} → next scene

By our reconstruction of its read path, emem range-reads 0.058 % of the scene to sign one NDVI value: three 64 KiB COG headers and one tile each of B04, B08 and SCL. It stores the 1,115-byte record, not the tiles. The next agent receives 84 characters (46 GPT-4 tokenizer tokens).

We hashed the Earth Search (AWS) copies of the B08 and B04 COGs into two signed pointer notes §2 §3: all 292 chunks of each (header + 291 tiles; 238.7 MB, 232.9 MB) under one Merkle root; the files stay on AWS. The tile holding the cell is emem:tree:khiqtqrddb6jponqn4gv72if7e#row=108 (row = leaf index); its 1,586,895 bytes hash to that row. These are not the Planetary Computer file the NDVI was read from (281.9 MB, offset not pre-subtracted), and emem records no hash of that file.

5 · Handoff: two LLMs, emem as the only MCP server

Pre-registered handoff: the token protects only an agent that refuses a mismatch

B acts ⇔ BLAKE3(b) = cid ∧ cell(b) = cell(token) · rule: irrigate ⇔ NDVI ≤ 0.4705 · Fisher exact, one-sided
B = Claude Haiku 4.5 receivesB correctB checked
A’s token10/10resolve, re-hash, receipt 10/10
A’s own prose (16 digits)10/10nothing to check
prose rounded to “0.47”0/5—

A: Claude Sonnet 5.5 with emem as its only MCP server returned the exact token in 10/10 runs (mean 13 s, 3.3 tool calls; one prose misdated the scene 2025). Rule: irrigate if NDVI ≤ 0.4705, a threshold set on purpose 0.0004 below the value so that 2-decimal rounding flips it; it shows the mechanism, not a rate. Primary test, token vs full prose: 10/10 vs 10/10, a tie (p = 1). The rounded arm was added after A’s runs (exploratory): Fisher p = 0.0003. The pre-registered local Qwen2.5-3B as B (42 of 45 trials run) read 0.4709 from the token yet chose irrigate, 0/19 correct (full prose 10/18); on forged tokens it dropped the cell, resolved the bare id and acted: 0/5 declined.

Pre-registration hashed before trial 1 (research/repro/data/v8/prereg.md). Claude arms: one model family for A and B.

9 · Since the paper was accepted

emem retired its foundation-model encoders

TESSERA: e = f32(qint8) × f32(scale), 128 dims, recomputable only as a re-read · device: trace_root = Merkle(segment digests); a fact binds ⇔ BLAKE3(CBOR(value)) ∈ outputs; admit ⇔ no reject reason of 17

The accepted paper builds on embeddings. Since then Clay v1.5, Prithvi-EO-2.0, Galileo and the JEPA-v2 head were removed from the code §23, and TESSERA is frozen on emem.dev; vectors signed before still resolve and verify §24.

The records show the difference. The TESSERA vector §9 re-reads bit-exact from its public product (128 B int8 + 4 B scale, max |Δ| = 0, 4 of 4), but it is attester_only: nobody can recompute the encoder step. The Clay vector §10 names its weights by BLAKE2b, and the code that ran them is gone. A raw band read §4 is recomputable by anyone from public bytes.

A device that cannot be recomputed must bind its output inside a complete OS execution trace. That gate ships as code, with conformance vectors; it admits no real hardware yet §26.

13 · What is not established

What a signature does not show

draft check allows ⇔ ∃ number a: round(a·10d)/10d = s, d = decimals written, s = signed value → “≈ 0.49” passes for 0.4871
A signature says who served a value, not that it is true.
A fact_cid names one signed record; two signers of the same value mint different ids.
Place and object (entity) tokens are labels; only fact, raster, cube and tree tokens hash bytes; a bundle hashes a citation list.
A signed “no tile here” §15 is a claim; no complete tile index backs it.
emem’s draft checker rejects “35 °C” citing a signed 28.0 °C §14, but it judges at the writer’s precision and allows “≈ 0.49”; it does not check band or unit.
Re-minting a raster yields a new token for identical pixels (signed_at is hashed).
One responder and one operator; the only domain-vouched log co-signer, geo.qa, is also Vortx AI (109 other witness keys are unvouched). No read federation, no hardware attestation, nothing in orbit.
The agent experiments are single-host samples without independent replication.
