EMEM: A Content-Addressed, Verifiable Earth-Memory Protocol for AI Agents over Foundation-Model Embeddings

Jaya Kumari · Avijeet Singh — Vortx AI · paper doi:10.5281/zenodo.20706893 (v0.1.0; current method: whitepaper v3, emem 213e273) · measurements 29–30 Sep 2026 · scripts: github.com/Vortx-AI/esa_poster
Agent A cites a satellite observation. What can agent B check without trusting A, A’s model, or us?

B receives an address, not a sentence. emem stores each observation as a signed record named by the BLAKE3 hash of its own bytes. B fetches the bytes, re-hashes them, verifies the signature offline, and can walk the record back to the source pixel in the Sentinel-2 file.

Token grammar: emem:fact:<cell64>:<fact_cid>. cell64 is a 64-bit ≈10 m grid cell; fact_cid = base32(BLAKE3-256(emem-CBOR bytes)). A token cited under the wrong cell returns HTTP 409.

1 · Satellite to agent

The scene stays on the archive. The agent gets 84 characters.

To sign one NDVI value, emem range-reads 0.058 % of the scene: three 64 KiB COG headers and one tile each of B04, B08 and SCL. It stores the 1,115-byte record, not the tiles. The next agent receives 84 characters (46 cl100k tokens).

The B08 and B04 COGs are themselves emem pointer notes §2 §3: all 292 tiles of each (238.7 MB, 232.9 MB) hashed under one Merkle root, the files left on AWS. The tile holding the cell is emem:tree:khiqtqrddb6jponqn4gv72if7e#row=108; its 1,586,895 bytes, range-read from AWS, hash to that row.

3 · What the trace found

emem’s own reads were one pixel south. The signatures made it findable.

Re-reading the COGs named inside the signed records showed that the 23 Sep record §7 carries the DNs of the pixel 10 m south (dashed red: 2993/1972, SCL 5 bare soil, NDVI 0.3444). The pixel that contains the point (blue) reads 0.4860. emem had rounded the fractional pixel index; GDAL takes the floor. The fix shipped on 28 Sep §8.

7 · Over foundation-model embeddings

A Tessera vector, re-derived by anyone

At the same cell, emem signs the 128-D TESSERA v1 (Cambridge; Sentinel-1 + Sentinel-2, 2024) embedding as a model_output record §9. Two range reads of the public product on Source Cooperative (128 B int8 + 4 B scale) give all 128 floats back with max |Δ| = 0; 4 of 4 facts tested match.

emem re-serves this product; it does not run the encoder, and the record says so (tamper_evidence: attester_only). Encoders emem did run, such as Clay v1.5 §10, pin the checkpoint by BLAKE2b.

8 · Fields and fields through time

One cube, five scenes, each date gap stated

An emem:cube: token §6 is a signed manifest of five raster records; each member states the date asked for and the scene used (+10 to +29 days). The 13 Sep member is cloudy: scenes are chosen by scene-level cloud cover (≤ 40 %, relaxed in tiers), not a pixel mask.

13 · What is not established

Boundaries

A signature says who served a value, not that it is true.
A fact_cid names one signed record; two signers of the same value mint different ids.
Entity tokens name things by agreement; only fact, raster and cube tokens bind bytes.
A signed absence is an assertion, not proof against a committed set.
The guard denies a draft that says 35 °C while citing the signed 28.0 °C §14 (PROV_VALUE), but it judges at the writer’s precision and allows “≈ 0.49”.
Re-minting a field yields a new token for identical pixels (signed_at is hashed).
One responder and one operator; the log co-signer is also Vortx AI. No read federation, no hardware attestation, nothing in orbit.
The agent experiments are single-host samples without independent replication.
